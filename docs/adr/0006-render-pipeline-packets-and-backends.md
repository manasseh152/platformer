# Render pipeline packets and backends

The renderer had several generations mixed together: gameplay rendering queried mutable game state directly, map snapshots reused drawing helpers, and presentation/upscaling was coupled to the old Canvas2D render facade. We chose a packet-based pipeline — extraction to finalized `RenderFrame` packets, then native-frame backends, then presentation backends — so gameplay/read-model extraction, backend drawing, asset resolution, and browser presentation have explicit boundaries. Generic packet/frame primitives live under `src/engine/render`; game/browser extraction, assets, backends, presentation, and snapshots live under `src/render`. Canvas2D is the first/reference native-frame backend, while WebGL/WebGPU work must stay behind backend contracts and capability/parity gates. Current implementation guidance lives in [`../patterns/rendering.md`](../patterns/rendering.md).
